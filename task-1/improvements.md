## Механизм тегирования данных

### Список тегов

#### По уровню конфиденциальности данных

- `PUBLIC` - публичные данные
- `INTERNAL` - внутренние данные
- `CONFIDENTIAL` - конфиденциальные данные
- `SECRET` - данные с высшим уровнем секретности

#### По ролям доступа сотрудников

- `SUPER_ADMIN` - для главных администраторы
- `ADMIN` - для ИТ и администраторов
- `ACCOUNTANT` - для бухгалтерии
- `MED_EMPLOYEE` - для медицинских сотрудников
- `RECEPTION_EMPLOYEE` - для сотрудников ресепшена
- `CLIENT` - для клиентов

#### По виду данных

- `PII` - персональные идентификационные данные
- `PHI` - защищенная медицинская информация
- `FINANCIAL_DATA` - платежные данные
- `OPERATIONAL_DATA` - операционные данные
- `LEGAL_DATA` - юридические данные

#### По длительности хранения

- `TEMPORARY` - временные данные
- `SHORT_STORAGE` - краткосрочное хранение
- `MEDIUM_STORAGE` - среднесрочное хранение
- `LONG_STORAGE` - долгосрочное хранение
- `PERMANENT` - постоянное данные

### Инструменты тегирования данных

Для небольшой компании с маленьким штатом рекомендуется использовать DataGrail для решения задачи тегирования данных,
который быстро интегрируется и легко настраивается

## Инструменты, способы и меры обеспечения конфиденциальности данных

### Технические меры

#### Защита данных с помощью шифрования

- Шифрование хранящейся информации
  - Файловое шифрование (например, медицинские сканы)
  - Шифрование в СУБД (конфиденциальные персональные данные)
- Шифрование передаваемых данных
  - Использование TLS/SSL для всех сетевых соединений
  - Применение VPN для удалённых подключений

#### Контроль доступа

- Ролевое управление доступом (RBAC) — начальный этап (MVP) как более простое решение
  - Назначение ролей сотрудникам в зависимости от их функций
  - Принцип минимальных привилегий для каждой роли
- Атрибутивное управление доступом (ABAC) — планируется в финальной версии
  - Доступ на основе комбинации атрибутов и меток
- Многофакторная аутентификация (MFA)
  - Обязательна для работы с критически важными системами и данными

#### Отслеживание и аудит безопасности

- Фиксация и анализ действий пользователей
- Логирование операций с конфиденциальной информацией
- Контроль и проверка доступа к данным

#### Обеспечение конфиденциальности данных

- Маскирование конфиденциальных сведений
- Токенизация данных
- Псевдонимизация информации

### Организационные меры

#### Повышение осведомлённости и обучение

- Систематическое обучение персонала
- Проведение тренингов по кибербезопасности

#### Контроль и минимизация рисков

- Периодическая оценка потенциальных угроз
- Мониторинг и устранение уязвимостей
- Регулярные проверки системы безопасности

#### Реагирование на инциденты

- Чёткие алгоритмы действий при нарушениях безопасности
- Назначение ответственных за ИБ (включая введение роли инженера по безопасности)
- Разработка планов аварийного восстановления
- Разбор и расследование произошедших инцидентов

### Архитектурные решения

#### Микросервисный подход

- Изолированные сервисы с ограниченными правами доступа
- Централизованное управление запросами через защищённые API-Gateway

#### Облачная инфраструктура

- Развёртывание на платформах ведущих облачных провайдеров
- Сквозное шифрование облачных данных
- Строгий контроль авторизации для облачных сервисов

#### Сегментированное хранение информации

- Физическое и логическое разделение данных по степени конфиденциальности
- Классифицированное хранение на основе метаданных и политик доступа

#### Подход Zero Trust

- Сквозная аутентификация всех транзакций
- Принцип наименьших привилегий для всех аккаунтов
- Непрерывная проверка активностей
- Периодические контрольные проверки системы

### **Ключевые улучшения:**

- Более чёткие технические формулировки
- Акцент на практическую реализацию принципов
- Улучшенная логическая последовательность
- Сохранение всех исходных требований безопасности
